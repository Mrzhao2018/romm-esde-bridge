RomM · ES-DE Bridge

一个游戏库，多台设备，按需游玩。

RomM 是游戏与元数据的唯一来源；Bridge 把它转成 ES-DE 可用的目录，并负责设备配对、按需缓存、存档状态和个人标记同步。客户端不需要保存完整 ROM 库。

系统怎样结合

1 · 管理ROM、BIOS、封面和元数据只在 RomM 维护。
2 · 发布Bridge 输出共享目录和每用户的安全覆盖层。
3 · 浏览ES-DE 显示 RomM 名称、说明、大小封面和收藏状态。
4 · 游玩点击时才下载到本机缓存，退出后回传进度和状态。

从同一份 RomM manifest 选择游戏，服务器端启动 NP2Kai；浏览器接收画面和输入，用户 token 约束下载、换盘和状态。

共享游戏与固件

所有用户复用服务器上的一份 ROM、BIOS 和媒体资源；客户端只保留自己玩过或主动缓存的内容。

个人数据隔离

不同 RomM 用户拥有各自的收藏、隐藏、游玩记录、存档与设备身份；同一用户的多台设备可以接续。

ES-DE 会话同步

启动 ES-DE 前同步目录与封面；运行时收藏/隐藏变化会立即推送；退出时再做一次收尾同步。客户端没有固定轮询常驻任务。

新设备一键部署

SteamOS / Linux

curl -fsSL @@BRIDGE_URL@@/bootstrap/install.sh | bash

Windows x64

在希望作为安装根目录的磁盘中打开 PowerShell；程序与缓存会跟随当前盘，不强制写入 C 盘。

irm @@BRIDGE_URL@@/bootstrap/install.ps1 | iex

使用原则

RomM 管“库”，ES-DE 管“浏览与启动”，模拟器管“运行”。Bridge 连接三者，但不复制 RomM 的管理职能。添加、改名、刮削或修正封面应优先在 RomM 完成；客户端会在下一次启动 ES-DE 时取得结果。
